## 2025-03-08 - bcrypt 72-byte Truncation DoS
**Vulnerability:** The `bcrypt` library silently truncates or fails on passwords longer than 72 bytes. This can be exploited by an attacker submitting extremely long passwords to cause Denial of Service (DoS) by maxing out CPU during hashing and error handling, or by bypassing authentication if passwords are truncated.
**Learning:** Bcrypt has a hard limit of 72 bytes for the input password due to the Blowfish cipher limitations. Older versions truncate silently, while newer versions (like the one used in the Author Studio Pro backend) raise a `ValueError`, which can cause internal server errors if unhandled, leading to DoS.
**Prevention:** Pre-hash user passwords using a fast hashing algorithm like `hashlib.sha256().hexdigest()` before passing them to bcrypt. To prevent collisions and ensure the hash is recognizable as a pre-hashed format, prepend a prefix like `$sha256$` to the output string. Ensure the login verification fallback handles both the new format and legacy bcrypt hashes to maintain backward compatibility.
