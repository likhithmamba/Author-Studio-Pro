## 2024-05-18 - [Bcrypt 72-Byte Limit DoS]
**Vulnerability:** The application was using the `bcrypt` library directly to hash passwords, which has a hard limit of 72 bytes. Submitting a longer password caused a `ValueError` that wasn't being caught, resulting in an unhandled exception (500 Server Error) that could be exploited for a Denial of Service (DoS).
**Learning:** Bypassing standard wrapper libraries (like `passlib`) due to environment/compatibility issues (e.g. Python 3.12 compatibility) means losing their built-in mitigations for underlying library limits. We must handle these limits explicitly.
**Prevention:** Implement SHA-256 pre-hashing before passing the password to `bcrypt`. This ensures all inputs are reduced to a fixed size (64 character hex string) well below the 72-byte limit. We store these new hashes with a `$sha256$` prefix to differentiate them from legacy hashes, ensuring backwards compatibility for existing users while securing the system against long-password DoS attacks.
