## 2024-05-15 - bcrypt 72-byte Limit Truncation Vulnerability
**Vulnerability:** The application was using bcrypt directly on user-provided passwords. Bcrypt silently truncates passwords after 72 bytes. This means that if a user has a very long password, anything after 72 bytes is ignored. This could lead to multiple different long strings successfully validating against the same hash, increasing the likelihood of successful collisions or brute-force attacks if long passwords are used, and acting as a DoS vulnerability.
**Learning:** Bcrypt has a fundamental 72-byte limit limitation. Relying on it directly to hash user inputs without pre-hashing them first exposes applications to unexpected truncation behavior. This is specific to `bcrypt` hashing.
**Prevention:** Always pre-hash passwords using a fast algorithm like SHA-256 (e.g., `hashlib.sha256(password.encode('utf-8')).hexdigest()`) before passing them to bcrypt. This ensures that the input to bcrypt is a consistent, fixed length that falls within the 72-byte limit, while still retaining the cryptographic strength of the original long password.
