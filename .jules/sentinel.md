## 2024-05-24 - [Auth Bypass & Hardcoded Credentials in Mock Auth]
**Vulnerability:** Developer mock authentication was accessible even when `ENVIRONMENT=production`, utilizing hardcoded credentials ("demo@example.com" / "password123"), and was vulnerable to timing attacks during string comparison.
**Learning:** Mock/demo authentication features present a severe risk of backdoor entry if not strictly disabled in production. Hardcoded credentials bypass secure configuration practices, and simple string matching can be exploited to guess secrets via timing attacks.
**Prevention:** Strictly gate mock functionality with `ENVIRONMENT != "production"`. Never hardcode credentials; source them from environment variables (e.g., `MOCK_DEMO_EMAIL`). Use `hmac.compare_digest` for all string comparisons involving sensitive values to thwart timing attacks.

## 2026-05-05 - [Path Traversal in File Loading]
**Vulnerability:** User-controlled input (`body.mode`) was directly concatenated into a file path (`f"prompt_templates/{mode}.txt"`) to open a file. An attacker could potentially pass path traversal sequences (like `../`) or arbitrary file names to read sensitive files from the server, as long as the file exists, because `os.path.exists()` would return true and the file would be opened and its contents read.
**Learning:** Directly interpolating user input into file paths is dangerous and leads to path traversal vulnerabilities. Even if the application attempts to check if the file exists, an attacker can still provide paths to sensitive files (e.g., `../../../etc/passwd` if no `.txt` extension check existed, or reading any `.txt` file they can reach).
**Prevention:** Always strictly validate user input against an allowlist of expected, safe values before using it in a file path. Do not rely on path checks or character stripping.
