## 2024-05-24 - [Auth Bypass & Hardcoded Credentials in Mock Auth]
**Vulnerability:** Developer mock authentication was accessible even when `ENVIRONMENT=production`, utilizing hardcoded credentials ("demo@example.com" / "password123"), and was vulnerable to timing attacks during string comparison.
**Learning:** Mock/demo authentication features present a severe risk of backdoor entry if not strictly disabled in production. Hardcoded credentials bypass secure configuration practices, and simple string matching can be exploited to guess secrets via timing attacks.
**Prevention:** Strictly gate mock functionality with `ENVIRONMENT != "production"`. Never hardcode credentials; source them from environment variables (e.g., `MOCK_DEMO_EMAIL`). Use `hmac.compare_digest` for all string comparisons involving sensitive values to thwart timing attacks.

## 2024-05-24 - [Path Traversal in AI Routes Template Loading]
**Vulnerability:** The AI route `analyze_signals` loaded prompt templates dynamically based on user input `mode` (`f"prompt_templates/{mode}.txt"`). By passing a mode with path traversal sequences like `../../../etc/passwd`, an attacker could potentially read arbitrary files on the server since it was only checking `os.path.exists()` before calling `open()`.
**Learning:** Loading internal template files based directly on unsanitized user input creates path traversal vulnerabilities. A common mistake is to assume prepending a directory or appending an extension is sufficient protection, which it is not against `../` traversal sequences.
**Prevention:** Strictly validate user input for template or file selection against an explicit allowlist of valid values (e.g., `["normal", "depth", "extended"]`) and default to a safe value instead of passing raw input directly into file path construction.
