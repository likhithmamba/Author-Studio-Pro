Character States — Full Specification
Character states track per-character timeline evolution. Each state record captures the character's role, arc phase, and emotional/functional position at a specific chapter. This is what allows the Signal Engine to detect flat arcs, orphan characters, and missing character development.
Data Schema
characterStates: { [charId]: { name, role, arc_phase, current_state, chapter_id } }
arc_phase values: 'introduction' | 'development' | 'conflict' | 'transformation' | 'resolution'
current_state: free-text snapshot of character's emotional/situational status
chapter_id: the chapter where this state snapshot was recorded
confidence_score: 0-1 (AI-extracted = 0.70, user-created = 1.00, user-confirmed = 1.00)
Supabase Table: character_states
id (uuid, PK), project_id (FK → projects), user_id (FK → auth.users)
character_id (text), character_name (text), role (text)
arc_phase (enum: introduction/development/conflict/transformation/resolution)
current_state (text), chapter_id (text), confidence_score (float4, default 0.70)
created_at (timestamptz), updated_at (timestamptz)
RLS Policy: project owner and collaborators can SELECT/INSERT/UPDATE/DELETE
Conflict States — Full Specification
Conflict states track the lifecycle and intensity of each conflict. The Signal Engine uses these to detect unresolved conflicts, missing escalation, and premature resolution.
Data Schema
conflictStates: { [confId]: { type, intensity: 0-1, parties, status, chapter_id } }
type values: 'internal' | 'interpersonal' | 'societal' | 'environmental'
intensity: float 0-1 representing conflict pressure level at this chapter
parties: string[] — character IDs involved in the conflict
status: 'active' | 'escalating' | 'resolved' | 'dormant'
Progression Markers — Full Specification
progressionMarkers: [{ id, chapter_id, phase: 'setup'|'escalation'|'peak'|'resolution', confidence }]
These drive the Progression Curve Engine and the graph overlay colour system
phase coloring: setup(blue) → escalation(amber) → peak(red) → resolution(green)
Node and Edge Typing — Full Specification
Node Types
scene — represents a narrative scene with chapter reference and word count
event — represents a plot event connected to a chapter
character — represents a character node with arc_phase badge
Each node must carry: node_type, confidence_score, chapter_id
Edge Types
causality — solid line with directional arrow. A causes B.
relationship — dashed line. Character A relates to Character B.
conflict — red animated line. Conflict between parties.

04 — Intent Layer
✗
Status: Entirely Missing — 0%
The Intent Layer makes the Signal Engine story-type and phase-aware. Without it, the engine produces false positives on intentional structure choices (e.g. slow burns, literary fiction). It modifies signal severity based on declared story type and current progression phase.
Intent Layer Specification
Reads: current_phase from progressionMarkers + story intent settings (stored in project metadata)
Story types: 'literary' | 'genre' | 'thriller' | 'romance' | 'slow_burn' | 'action'
Each story type defines expected conflict_intensity ranges per phase
If actual metrics fall within expected range → do NOT fire severity signals
If actual metrics deviate significantly → elevate signal severity
Phase-Aware Modifiers
setup phase + conflict_intensity < 0.3 → lower pacing signal severity by 2 levels
setup phase + flat arc → suppress arc signal (intentional in setup)
escalation phase + flat middle detection → HIGH severity (critical signal)
peak phase + missing peak marker → CRITICAL severity
resolution phase + unresolved conflicts → HIGH severity

08 — Progression Curve Engine
✗
Status: Entirely Missing — 0%
The spec defines four metrics (setup_density, conflict_intensity, event_frequency, resolution_pressure) and a curve shape (setup → escalation → peak → resolution) used to detect flat middles, pacing imbalances, and weak escalation. None of these metrics are calculated anywhere, and there is no curve visualisation.
Metric Definitions
setup_density: count of progression_markers with phase='setup' in chapter / total markers
conflict_intensity: avg(conflictStates[].intensity) for conflicts active in chapter (0-1)
event_frequency: count of event-type nodes in chapter / avg events across all chapters
resolution_pressure: count of unresolved conflicts / total conflicts at chapter point
Curve Shape Detection Rules
flatMiddle: chapters 30-70% of novel where conflict_intensity delta < 0.1 across 3+ consecutive chapters
weakEscalation: conflict_intensity at chapter 75% < conflict_intensity at chapter 50%
missingPeak: no chapter with conflict_intensity > 0.8 in the entire novel
earlyResolution: resolution_pressure drops to 0 before chapter 85%
PROMPT TEMPLATE — Progression Curve Engine
Target: src/utils/progressionCurve.js
// Build the progression curve calculator and detection system.
// For each chapter in chapterOrder:
setup_density = count(progressionMarkers where phase='setup' and chapter_id=chapter.id) / total markers

resolution_pressure = count(conflictStates where status='active') / total conflicts at chapter point

flatMiddle: chapters 30-70% where conflict_intensity delta < 0.1 across 3+ consecutive chapters
weakEscalation: conflict_intensity at ch75% < conflict_intensity at ch50%

16 — EXECUTION CONTRACT (MANDATORY)
16.1 Master Orchestrator
runFullAnalysis(projectId: string, mode: 'normal' | 'depth' | 'extended') -> AnalysisResult
 
Steps:
1. snapshot = getSSO(projectId)
2. signals = runSignalEngine(snapshot)
3. metaSignals = mergeMeta(signals)
4. progression = progressionCurve(snapshot)
 
5. IF mode == 'normal':
     insights = runAIAnalysis({ signals, phase }, 'normal')
 
   IF mode == 'depth':
     insights = runAIAnalysis({ signals, metaSignals, progression, states }, 'depth')
 
   IF mode == 'extended':
     TRY:
       insights = runAIAnalysis(fullContext, 'extended')
     CATCH timeout/token_error:
       fallback -> run depth mode
 
6. return AnalysisResult
16.2 Function Contracts
getSSO(projectId) -> SSO_Snapshot
 
runSignalEngine(snapshot: SSO_Snapshot) -> Signal[]
 
mergeMeta(signals: Signal[]) -> MetaSignal[]
 
progressionCurve(snapshot: SSO_Snapshot) -> CurveData
 
runAIAnalysis(input: object, mode: string) -> Insight[]
16.3 Final Output Schema
AnalysisResult = {
  mode: 'normal' | 'depth' | 'extended',
  signals: Signal[],
  metaSignals: MetaSignal[],
  progression: CurveData,
  insights: Insight[],
  timestamp: number
}
